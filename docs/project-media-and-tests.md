尚未提供的图片和测试不能作为已完成成果展示。

## 第一批：先提供这些

| 材料 | 拍到 / 保存什么 | 用途 |
| --- | --- | --- |
| 硬件总览照片 | STUDYBOARD、OV5640、LCD、网线和电脑的连接；横向、清晰、光线充足 | 放在首页开头，展示实物系统 |
| LCD 人脸框照片 | LCD 上的摄像头画面和红框，同时保留屏幕边框或部分板卡 | 证明是板端检测显示 |
| 双端联合演示 | 同时拍 LCD 和 PC；人物/物体移动，PC 显示源序号与帧率 | 展示四条处理路径共同运行 |
| 完整运行日志 | 从启动命令、模型/线程信息开始，到 Ctrl-C 后所有 summary | 支持性能表和复现 |

图片可先提供普通 JPG/PNG。视频建议 20–40 秒，覆盖画面运动与人脸进入、
离开镜头。只提供你允许在公开仓库展示的照片和人像。
建议图片最长边约 1600–2000 像素，终端文字和检测框仍可辨认；不要只给缩小后
看不清文字的拼图。视频可给公开演示链接，或先提供文件再选发布方式。
当前 `.gitignore` 排除 MP4，不会自动把视频提交进源码。

## 完整运行日志应有的条件

- 实际启动命令：模型尺寸、线程数、LCD 模式、预览与网络抽帧参数。
- 开头 `model:`、`parallel_runtime:`、`settings:`、`preview:`、`network:`。
- 末尾 `capture_summary`、`inference_summary`、`average_ms`、`lcd_summary`、
  `network_summary` 和退出码。
- `uname -r`、程序与模型 SHA256、运行时长，是否有其他负载。
- LCD/PC 是否全程更新，有无花屏、停顿、错色和框漂移。

不必为补 README 重刷 SD 或重编译；当前包再次运行时记录即可。
运行过程中不要为了取图再启动第二个摄像头读取程序。

当前功能是人脸检测，不是人员身份识别。

## 推荐性能对照

硬件、相机和场景尽量相同，一次只改一个变量：

1. 同一模型、线程和 LCD 模式，比较关闭/打开网络发送。
2. 同一权重的成套导出，比较 320/224/192，完整记录每次启动参数。
3. 固定模型，比较 stride=6 与更低发送率，记录带宽、PC 帧率和推理耗时。
4. 记录较长持续运行、Ctrl-C 后重启，以及 PC 断开再连接的行为。

采用相同测试时长或帧数，记录运行顺序，必要时首尾重复基线。
分别报告采集 fps、推理耗时、LCD 发布率、PC 接收率、CPU 和内存占用。
端到端延迟应专门测量，例如同时拍摄计时器和接收画面；不能用 FPS 倒数代替。

以上是可选证据增强，不是本次修改 README 的前置条件。
现有联合测试按[归档记录](validation/network-joint-run-2026-10-16.md)展示。
