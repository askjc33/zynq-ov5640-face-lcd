# 上板运行与更新操作手册

本章以 **2026-10-13 已存在的 SD 卡目录**为例。先在开发板用 `ls` 确认目录确实存在；目录不存在时，不要把示例命令原样执行或覆盖其他版本。命令框上方标明执行环境，三种终端不可混用。

## 1. 运行环境与保留目录

| 环境 | 用途 | 提示符示例 |
| --- | --- | --- |
| Windows PowerShell | 配置直连网卡、SSH/SCP、看图片 | `PS C:\Users\Temp>` |
| Ubuntu 虚拟机 | PetaLinux/SDK 交叉编译 | `ubuntu@ubuntu:~$` |
| ZYNQ 开发板串口或 SSH | 操作摄像头、V4L2、LCD、SD 卡 | `root@ALIENTEK-ZYNQ:~#` |

板上已知的三个独立包：

| SD ext4 目录 | 角色 | 日常选用 |
| --- | --- | --- |
| `/media/sd-mmcblk0p2/face-lcd-recovery-20261012-01` | 早期已验证的“检测帧与显示帧一致”回退基线 | 特殊故障时回退 |
| `/media/sd-mmcblk0p2/face-lcd-preview-20261012-01` | 320 输入、流畅预览的已知可用基线 | 稳定性优先 |
| `/media/sd-mmcblk0p2/face-lcd-speed-20261013-01` | 192/224/256/320 输入对比的独立试验包 | 速度优先试用 192 |

不要把本机 `/home/root` 当成持久数据目录。本项目过去出现过重启后该目录里的模型和程序消失；现在以已验证的 SD ext4 目录为持久位置。启动脚本没有被安装为开机自启服务：**上电进入 Linux 后仍需手动执行**下面的命令。

## 2. 每次上电的最短操作

先接通电源、串口和屏幕，确认 Linux 登录提示符出现。若直连网线，Windows 的以太网口设为 `192.168.10.1/24`，板上 `eth0` 应为 `192.168.10.2/24`。网络不通不妨碍通过串口运行程序。

在**开发板**查看挂载和包：

```sh
mount | grep mmcblk0p2
uname -r
ls -ld /media/sd-mmcblk0p2/face-lcd-speed-20261013-01
ls -l /dev/video0
```

速度优先试用 192 输入、持续运行：

```sh
cd /media/sd-mmcblk0p2/face-lcd-speed-20261013-01
STUDYBOARD_LCD_MODE=preview STUDYBOARD_MODEL_SIZE=192 sh ./start-face-lcd.sh 0
```

`0` 是**采集帧数无限**，不是“不运行”。正常情况下按 `Ctrl+C` 退出，程序会停止 V4L2 和 LCD DMA、打印统计并保存最后一帧 PPM。若只做约十秒的冒烟测试，将尾部 `0` 换成 `300`。启动脚本会检查内核版本、程序和模型文件、摄像头五帧、LCD 扩展模块五帧；传感器初始化按 Linux `boot_id` 每次开机最多做一次。请不要先手工连续运行 `ov5640-init`，也不要在 V4L2 应用运行时手写 `running`/`display_running`。

稳定基线（320 输入）启动：

```sh
cd /media/sd-mmcblk0p2/face-lcd-preview-20261012-01
STUDYBOARD_LCD_MODE=preview sh ./start-face-lcd.sh 0
```

上述脚本若报错，应先按第 04 章定位，不要直接尝试 `STUDYBOARD_FORCE_SENSOR_INIT=1`。脚本默认 `STUDYBOARD_MODEL_SIZE=320` 且默认 LCD 模式为 `matched`；因此速度试验的 `192` 和流畅预览的 `preview` 必须显式设置。`STUDYBOARD_PREVIEW_STRIDE=2` 是默认值，表示大约每两帧摄像头图像向 LCD 发布一次；它不改变模型推理速度。

## 3. 看懂运行结果

一次正常输出至少应出现：

```text
V4L2 stream started: 640x480 BGR24
model: input=... [1,3,192,192], output=... [1,5,756]
lcd_output: ... mode=preview
inference=... faces=...
capture_summary: frames=... sequence_gaps=0 bad_payloads=0
inference_summary: processed=... skipped_stale=...
average_ms: ... inference=...
lcd_summary: frames=...
```

其中 `faces=0` 只是该次采样未检出脸，并不说明抓帧失败。`capture_summary` 的 fps 是摄像头吞吐，不是检测 fps；`lcd_summary` 是屏幕发布次数，也不是检测 fps。`skipped_stale` 代表模型还在推理时，用“最新帧邮箱”主动跳过旧图，防止结果越来越落后。退出后紧接着运行 `echo "return=$?"`，避免先执行其他命令覆盖退出码。成功通常为 0；按 `Ctrl+C` 后具体退出码取决于脚本/信号处理，应以完整统计和设备停止状态一起判断。

只读状态检查：

```sh
P=/sys/bus/platform/devices/studyboard-frame-capture
cat "$P/lcd_status"
grep xilinx-dma-controller /proc/interrupts
dmesg | tail -n 30
```

不要用 `/proc/interrupts` 的**绝对值**判断当前是否工作；记录启动前后相同 IRQ 的计数差。`lcd_status` 帧数增长意味着驱动接收了发布，不单独证明屏上画面或方框正确。最终仍需人眼观察屏幕和保存图。

## 4. 有限时长验收与保存图片

在开发板执行 300 帧测试：

```sh
cd /media/sd-mmcblk0p2/face-lcd-speed-20261013-01
STUDYBOARD_LCD_MODE=preview STUDYBOARD_MODEL_SIZE=192 sh ./start-face-lcd.sh 300
echo "return=$?"
ls -lh ./face-lcd-last.ppm
```

最后的 PPM 是 640×480 原图叠框，用于核查推理结果。**Windows PowerShell** 将其复制到已有的 `D:\share`：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa "root@192.168.10.2:/media/sd-mmcblk0p2/face-lcd-speed-20261013-01/face-lcd-last.ppm" "D:\share\face-lcd-last.ppm"
```

Windows 照片查看器一般不直接识别 PPM。若 YOLO Conda 环境中已装 Pillow，在 **Windows PowerShell** 转成 PNG：

```powershell
python -c "from PIL import Image; Image.open(r'D:\share\face-lcd-last.ppm').save(r'D:\share\face-lcd-last.png')"
```

再核对 PNG 的红框是否与实际人脸位置相符。若只有 `faces=0`，先让脸处于光照较好、大小和姿态合适的位置；不要只凭一次结果改阈值或重训。

## 5. 网络连接与文件传输

直连网线没有 DHCP 服务器时，`udhcpc` 持续发送 `discover` 属正常现象。通过**板端串口**检查或临时设 IP；不要在正在使用的 SSH 会话里 `ip addr flush dev eth0`，否则会立即切断会话：

```sh
ip link show dev eth0
ip -4 addr show dev eth0
ip link set eth0 up
ip addr add 192.168.10.2/24 dev eth0
ping -c 3 192.168.10.1
```

若已存在 `192.168.10.2/24`，不要重复添加。**Windows PowerShell** 连接：

```powershell
ping 192.168.10.2
ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.10.2
```

旧版 Dropbear 只提供 `ssh-rsa` 主机密钥协商时，上述选项用于这块受控的实验板；不要把 `StrictHostKeyChecking=no` 作为长期解法。若 SSH 报 **REMOTE HOST IDENTIFICATION HAS CHANGED**，先通过可信串口核验当前板子的 RSA 指纹，确认是 SD/主机密钥重建后，才在 Windows 运行 `ssh-keygen -R 192.168.10.2` 并重新接受已核验的新密钥。`ping` 通只说明 ICMP 互通，不说明 SSH 身份验证或服务正常。

把一个**已构建的新版本目录**传到 SD 的单条 PowerShell 命令示例：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa -r "D:\share\studyboard_face_speed_20261013\speed-update-20261013-01" "root@192.168.10.2:/media/sd-mmcblk0p2/"
```

复制前先确认本机源目录存在、目标 SD 挂载正确、同名目标尚不含需要保留的数据。传输不是每天必须做的事：**SD 卡文件持久存在**，仅新版本发布或 SD 文件损坏才需要重新传。

## 6. 什么时候要重新构建

| 改了什么 | 需要什么 | 不需要什么 |
| --- | --- | --- |
| 只换运行参数：192/224/256/320、`matched`/`preview`、采集帧数 | 在现成速度试验包里切环境变量 | 重训、编译、刷卡 |
| 模型权重/导出尺寸改变 | 重新导出 NCNN，配套 param/bin 和哈希校验，再独立部署 | 不一定重编驱动/内核 |
| 用户态预处理、后处理、调度改变 | SDK 交叉编译应用、独立包验收 | 不一定重编驱动或 `image.ub` |
| V4L2/LCD 内核驱动改变 | 同运行内核版本编译 `.ko`，校验 `KERNEL-RELEASE`，备份回退 | 通常不需重训 |
| PL bitstream、设备树、内核配置改变 | 重新构建并核查 `BOOT.BIN`/`image.ub`，按安全流程更新启动介质 | 不是日常调参步骤 |

本次速度试验的 **Ubuntu 虚拟机**构建入口是：

```sh
bash /mnt/hgfs/share/studyboard_face_speed_20261013/build-speed-variants.sh
```

它依赖已安装的 PetaLinux SDK 与 NCNN SIMPLEOMP 构建产物，生成独立速度更新目录。只有代码、模型或构建环境确实变更时才运行；构建前阅读脚本里的输入/输出目录，避免覆盖已留作证据的试验包。普通应用交叉编译应使用 `images/linux/sdk/environment-setup-cortexa9t2hf-neon-xilinx-linux-gnueabi`，不要误把 `components/yocto/environment-setup-*` 当成已安装 SDK。`LD_LIBRARY_PATH` 若污染 SDK，应在单独的新 shell 中核查并安全地取消该变量。

## 7. 回退与收尾

如果 192 图像质量或稳定性不满意，停止当前程序后回到不被试验覆盖的 320 预览包：

```sh
cd /media/sd-mmcblk0p2/face-lcd-preview-20261012-01
STUDYBOARD_LCD_MODE=preview sh ./start-face-lcd.sh 0
```

如果需要“推理帧直接显示”的旧版基线，可在停止当前程序后使用 `/media/sd-mmcblk0p2/face-lcd-recovery-20261012-01` 的 `start-face-lcd.sh`。不要同时启动两个 `/dev/video0` 消费者；更不要为了回退去删除已知可用目录。准备断电或拔 SD 时，先 `Ctrl+C` 结束程序、确认停止信息，再用系统正常关机流程。此前 FAT 启动分区曾出现 dirty bit，突然掉电会增加文件系统风险。
