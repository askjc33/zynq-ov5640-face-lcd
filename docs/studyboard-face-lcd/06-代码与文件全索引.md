# 06｜代码与文件全索引（2026-10-14 仓库快照）

本章回答“到底该看哪个文件”。仓库约 5,800 个文件，其中 `build/` 约 5,338 个是 Vivado/SDK 工程和中间产物；不能把每个 `.xpr/.dcp/.rpt/.log` 当成一份独立算法源码。本章逐项覆盖人工维护的目录和文件，对图像、模型、生成文件按**类型和生产者**说明。路径均以仓库根目录为基准；没有上板证据的版本关系不能用目录名推断。

## 0. 三条产品线

```text
仓库
├─ 原始/移植的 HDMI 帧差：OV5640 → PL 帧差 → DDR → HDMI；SDK 裸机 C
├─ ATK-MD0430 LCD 帧差：OV5640 → PL 帧差 → DDR → 8080 LCD；SDK 裸机 C
└─ 当前 Linux 人脸检测：采集/LCD PL 通路 → V4L2 → NCNN → LCD
```

三条线复用摄像头、VDMA 和部分 PL，但**裸机 `SDK/main.c` 不在当前 PetaLinux 人脸程序中运行**，HDMI 也不是当前 LCD 验收结果。当前主线应优先读 `linux/`，用 `scripts/create_studyboard_lcd_project.tcl` 理解 PL 连接。仓库的 LCD Block Design 实例化 `frame_difference_axis_bram`；若当前启动镜像由该设计构建，V4L2 原图在进入 DDR 前可能已经叠加 PL 的白色运动框，而 NCNN 在用户态另外画红色人脸框。要确认板上 bitstream 版本，需比对启动文件/XSA 的来源和哈希。

源码来源也不同：部分 `SDK/`、`ip_repo/` 文件带有正点原子或其他供应商的版权/接口声明，Vivado 还会生成大量 IP 包装文件；不能把仓库内**所有代码**都说成是本轮重新原创生成。保留原许可和来源记录，修改时先认清文件身份。

快速打开当前 Linux 主线：[启动入口](../../linux/studyboard_ncnn_face/start-face-lcd.sh) · [运行参数脚本](../../linux/studyboard_ncnn_face/run-face-lcd.sh) · [C++ 主程序](../../linux/studyboard_ncnn_face/studyboard-ncnn-face.cpp) · [检测器](../../linux/studyboard_ncnn_face/face_detector.cpp) · [LCD 适配器](../../linux/studyboard_ncnn_face/lcd_output.cpp) · [V4L2/VDMA 驱动](../../linux/studyboard_frame_capture/studyboard-frame-capture.c) · [设备树片段](../../linux/studyboard_frame_capture/studyboard-frame-capture.dtsi) · [传感器初始化](../../linux/ov5640_init/ov5640-init.c)。

## 5. `ip_repo/`、`output/`、`build/` 的定位

- `ip_repo/ov5640_cap_data/SRC/ov5640_capture_data.v`：摄像头 DVP 接收/像素组织；`component.xml`/`xgui` 管 Vivado 封装。
- `ip_repo/rgb2lcd/ip/rgb2lcd/src/rgb2lcd.v`：原有 RGB→LCD IP，与当前 `rtl/axis_nt35510_display.v` 路线区分；其 `if/*.xml`、GUI/组件文件是元数据。
- `ip_repo/DVI_TX/ip/src/{dvi_transmitter_top,dvi_encoder,serializer_10_to_1,asyn_rst_syn}.v`：HDMI/DVI TMDS 传输链，不是当前 8080 LCD 路径；XML/Tcl 为 IP 封装。
- `ip_repo/axi_dynclk_v1_0/src/*`：AXI 动态时钟 RTL；`drivers/` 和 `axi_dynclk/src/` 的 C 文件是显示/时钟驱动包装层，主要服务 HDMI 裸机，不是 Linux 内核模块。
- `output/bit/`、`output/full/`、`output/lcd_full/`：bitstream、ELF、HDF/HWDEF 和时序/资源报告；`output/lcd_full/` 是裸机 LCD 阶段，不是板上 PetaLinux `image.ub`。
- `output/studyboard_face_lcd_step1/`、`output/studyboard_face_speed_20261013/`：传输用**源快照/交付包**，`app/driver/sensor/` 与 `linux/` 有副本。已核对 speed 快照中 detector 主源、主程序和 `run-face-lcd.sh` 与 `linux/` 对应 SHA256 一致；其他副本不能仅凭同名认定相同。
- `output/face_speed_256/`：测试集副本、`best.pt`、NCNN 导出、`eval.py`（PyTorch 同权重不同尺寸）、`eval_ncnn.py`（NCNN 导出验证）、结果 JSON；`__pycache__` 等为生成缓存。
- `build/`：Vivado/XSCT 工作区、BD、IP 实例、缓存、综合实现日志、`.xpr/.xsa/.dcp` 等约 5,338 个文件；可追溯具体实现，但通常不逐个手改。

经验规则：**改行为找正本，改部署找脚本/recipe，模型换成套 param+bin，生成物与交付快照当证据**。修改前先核对板上 `uname -r`、`KERNEL-RELEASE`、`SHA256SUMS`、运行日志和启动镜像来源。多份同名代码须比对哈希，不能编辑 `output/` 某一份就假定 PetaLinux 会自动读取。
