# StudyBoard 人脸检测与 LCD 系统手册

版本：2026-10-13（依据目前已见的板端日志和本仓库源码）。对象：第一次接手本项目、需要自己运行、排错、修改和复现的人。

> 本仓库最初的 HDMI 帧差实验与这里的 **OV5640 → V4L2 → NCNN → LCD** Linux 支线不是同一条验收链路。本手册只把后者称为“人脸检测系统”，不把前者的功能或测试结果算作本系统已完成。

## 先读结论

- 实物已经完成 640×480 摄像头采集、V4L2 抓帧、单类人脸检测、LCD 原图/预览叠框。
- 采集约 28.5 帧/秒；`preview` 模式向 LCD 发布约每秒十余帧；**检测**不是这个速度。320 输入约 0.98 次/秒，192 输入在 600 帧对照中约 2.61 次/秒。
- 192 是“速度优先”的**试验选择**，不是已经固化的开机默认值。其额外目视复测为 530 帧/18.571 秒；尚未收到 192 的五分钟长测结果。
- 320 的已知可用 preview 运行包经过 9000 帧/314.828 秒长测，以及重启/重新上电后的**手动**启动验证。尚未安装开机自启服务。
- 当前测试集较小、缺少多人和纯背景等充分验证；不能把 PC 上的高 mAP 直接写成现场准确率保证。

## 三条操作原则

1. 日常运行不需重训、不需编译、不需重刷 `BOOT.BIN`/`image.ub`。系统已验证的 SD 目录与速度试验目录要分开保存。
2. 先判断故障层级：传感器 ID/寄存器读回通过，不等于 DVP 有图像；LCD 发布计数增长，不等于人脸框准确；ping 通，不等于 SSH 登录成功。
3. 任何会改动驱动、模型或启动项的试验，都先记录原版本、校验值、运行日志和回退命令。对历史故障的解释以**已有证据**为限，不猜测未经证实的根因。
